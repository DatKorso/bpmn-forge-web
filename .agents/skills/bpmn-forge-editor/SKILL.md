# BPMN Forge Editor

Use the relevant source and its closest test first. Consult `.planning/quick/` or `git log -- <path>` when the rationale for a specific behavior matters. Check current test commands in `package.json` and `playwright.config.js`.

## Alignment

- Pick the layer by the symptom. `src/layout.js` handles graph order, rows and spacing. `src/alignment-plan.js` orchestrates whole-diagram alignment, `src/scope-plan.js` builds and refines candidates, `src/selection-plan.js` handles selection planning, `src/alignment-selection.js` checks eligibility synchronously, and `src/container-fit.js` fits containers and lanes. `src/route-flows.js` handles sequence flows, `src/pool-layout.js` handles pool placement and message flows, and `src/annotation-layout.js` handles linked notes and associations. Gateway label geometry lives in `src/gateway-label-layout.js`.
- Keep planner changes in the snapshot-to-plan path. Load layout planners on demand when the user triggers alignment. `src/auto-align.js` applies bounds and DI through `editor.autoAlign`. Keep nested waypoint and label commands in `postExecute` so a single undo restores pre-alignment geometry and label DI, including labels that originally lacked DI bounds. Check `keepFractionalBounds` in `src/main.js` if geometry drifts after reopening an export.
- Preserve BPMN relations and lane membership. For selection, preserve stationary geometry while allowing owned containers, linked notes and affected routes to update under existing planner rules. An infeasible selection leaves the model untouched. Whole-diagram alignment can report skipped regions.
- Preserve clear straight continuations and default branches where feasible. Minimum gaps constrain placement. Maximum gaps are soft and use diagram axes, including in vertical pools. Reuse clearance and routing checks when adding a placement candidate.
- For whole-diagram alignment, detect a compact loop in process coordinates from its incoming geometry in `src/layout.js`. In `src/compact-loops.js`, try the upper task's placement over the left gateway after pool, lane and annotation layout. Keep the task's calculated height and preserve the other bounds and routes. Require a straight main flow, a vertical return and a one-bend entry without worsening spacing or route interactions. Use `compact-loop.bpmn`, `vertical-compact-loop.bpmn`, and `e2e/alignment.spec.js` to verify this workflow.
- For BPMN geometry goldens, add the diagram under `test/fixtures/`. Review bounds, routes and skipped regions whenever updating the expected JSON. For an isolated geometry regression, extend the closest fixture in `test/alignment-plan.test.js` or `test/layout.test.js`. Assert the affected bounds or routes, and repeat alignment when changing candidate selection or routing. For command or export changes, reuse `e2e/alignment.spec.js` and `tight-pool.bpmn`. Compare exported DI and BPMN relations across undo, redo and reopening.

## Экспериментальная раскладка по графу

- Кнопка «Перестроить по графу β» вызывает `planGraphDiagram` в `src/auto-align.js` для активной плоскости. `src/main.js` фиксирует модель, корень и монотонную ревизию истории до ожидания кадра, проверяет их перед расчётом и предпросмотром и после подтверждения. Корень и история могут вернуться к прежнему состоянию за время ожидания. Подтверждённый план применяется одной командой. Учитываются минимальные или единые отступы.
- `src/graph-layout/index.js` собирает атомарный план. `support.js` сопоставляет видимые фигуры, участников, дорожки, действительные концы связей и DI активной Collaboration. BPMNEdge скрытого сообщения и отсутствующий BPMNEdge двух видимых концов вызывают адресный отказ. Сообщение без DI со скрытым концом остаётся в модели и попадает в диагностику. `model-order.js` получает узлы и полный список SequenceFlow из `flowElements`, ставит default первым, затем учитывает явные `outgoing`, затем порядок модели. Для выбора обратных рёбер DFS внутри SCC перебирает входы и остальные узлы в порядке модели. При топологическом обходе DAG для ELK готовые узлы выбираются по приоритету default-потока, затем по порядку дорожек и порядку модели. Канонические ключи передаются в маршрутизатор.
- `elk.js` лениво загружает ELK 0.12.1. `arrange.js` сохраняет продольный порядок ELK, размещает полосы дорожек, привязывает события к хостам и раскладывает раскрытые подпроцессы снизу вверх. Если у хоста одно граничное событие с выходом из его блока, событие размещается у дальнего края в направлении процесса. Центры хостов привязаны к сетке scope. В процессе без пула исходная геометрия задаёт общий сдвиг.
- `collaboration.js` раскладывает каждый пул в локальных координатах и ставит пулы одной ориентации по исходным центрам. Порядок участников в модели разрешает равенство. Общий левый верхний угол служит якорем, зазор на пути сообщения составляет как минимум 80 px, пустые пулы сохраняют размеры. После фиксации SequenceFlow и подписей шлюзов заметки следуют за опорой по итоговой дельте. При выборе опоры учитывайте структурный контейнер, пул и порядок модели. Для одиночной плоскости используется прежний проход аннотаций и подписей шлюзов.
- `collaboration-routes.js` строит MessageFlow, их подписи и Association по итоговым рамкам. Проверяйте стыковку с контуром, направленный выход из содержащих рамок и вход в них, отсутствие прохода через чужие пулы, заголовки и хосты граничных событий. Исходные waypoints MessageFlow и Association исключены из кандидатов. Явные позиции подписей применяются после маршрутов с отключённым `LabelBehavior` для этих связей. Undo восстанавливает исходное наличие BPMNLabel, повтор после применения и открытия экспорта оставляет историю и DI без изменений.
- R1–R4 относятся к рамкам и потокам последовательности. Для циклов исключение по направлению относится к выбранным рёбрам внутри SCC и петлям после сведения граничных событий к хостам. Маршруты стыкуются с реальными фигурами. В ELK ассоциации данных направлены к узлам данных, при применении их маршрутизирует bpmn-js с исходным направлением BPMN. R5 измеряет прямоту default-потоков. R6 требует совпадения нормализованных рамок и маршрутов SequenceFlow при возмущении входного DI. Размещение аннотаций и подписей должно сохранять эти рамки и маршруты. R7 проверяется в редакторе и после открытия экспорта.
- Для обходных маршрутов графовый планировщик сначала использует сетку с зазором 16 px от фигур. Он пробует стандартные 8 px, если маршрут не найден или если это может сократить число пересечений либо общую длину наложений. Поиск учитывает направление входа в точку и исключает немедленный разворот на том же отрезке, в том числе у порта. Проверяйте зазор на `acyclic-reorder`, оба обхода на `graph-layout/two-shortcuts` и разделение потоков на `invoice-approval`.
- Граница зависимостей проверяется в `test/graph-layout-boundary.test.js`. Общие модули включают `route-flows.js`, `routing-bounds.js`, `alignment-state.js`, `annotation-layout.js`, `finish-annotations.js` и геометрические примитивы `layout.js`. Планировщики всего документа, области, выделения и оптимизация компактных петель принадлежат старому движку.
- Запускайте `node scripts/graph-layout-quality.mjs --check-routes` при оптимизации маршрутизации. Снимок в `test/fixtures/graph-layout-baseline.json` хранит исходные метрики и отпечатки точных маршрутов обоих движков, включая 240 прогонов прототипа с возмущённым DI. `graph-layout-current.json` хранит отличия принятого варианта. Для записи отличий используйте `--snapshot`. `node scripts/graph-layout-placement.mjs` отдельно измеряет порядок ветвей и сдвиги после локальной правки. Ключ `--quality` проверяет R1–R6, общие сегменты и потолок пересечений. Список потоков R5 и исключения с причинами находятся в `test/helpers/graph-straight-flows.js`. Изменения снимка и допустимые ухудшения фиксируйте в `DECISION.md`.
- Запускайте `node scripts/graph-layout-prototype.mjs` для замеров R1–R6, сравнения со старым движком и проверки стоп-критериев на `tight-pool` и `vertical-pool`. `node scripts/benchmark-graph-layout.mjs` измеряет план для процесса из 200 узлов, четырёх пулов по 50 узлов и позднего отказа. После сборки `BPMN_GRAPH_BENCHMARK=1 npm run test:e2e -- e2e/graph-layout-benchmark.spec.js --workers=1` измеряет предпросмотр и длинные задачи Chromium на тех же сценариях. Проверки движка живут в `test/graph-layout.test.js`, `test/graph-layout-support.test.js` и `test/graph-collaboration*.test.js`. Сценарии команды, смены корня и экспорта живут в `e2e/graph-layout.spec.js`.

## Document and controls

- `src/main.js` stages imports before replacing the live model and tracks the download checkpoint by command identity. Preserve the live diagram and history on failure. Check undo, redo and a new history branch in `e2e/document.spec.js`.
- Use `src/toolbar.js` for preview confirmation and `src/footer.js` for progress and skipped-region reports. Plan first, then apply the prepared command after confirmation. Keep cancellation free of model changes. After closing the preview, re-enable the controls and explicitly restore focus to the initiating element because the browser may have remembered a different element while that control was disabled. Use the same path for both alignment shortcuts. Use `src/keyboard-palette.js` and `src/viewport.js` for keyboard placement and canvas navigation. Check focus and the affected path in `e2e/alignment.spec.js` or `e2e/viewport.spec.js`.

## Verification

Run targeted Node tests for planner changes. For editor workflows, build first with `npm run build`, then run `npm run test:e2e -- e2e/<spec>.spec.js` with the matching spec. Playwright serves `dist/` via Vite preview. Use the full suites for changes that span multiple workflows.

## Updating bpmn-js

Keep version-sensitive imports and methods in `src/bpmn-internals.js`. After changing the pinned dependency and lockfile, run `npm ci`, `npm test` (including the adapter signature test), `npm run build` and `npm run test:e2e`. Check the alignment spec for manual edits after alignment, unchanged BPMN relations, undo and redo, and export/reopen. Check the document spec for download checkpoint behavior.
