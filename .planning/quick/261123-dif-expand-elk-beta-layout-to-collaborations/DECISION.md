# Приёмка многопуловой раскладки ELK β

## Совместимость

Расширенный путь работает на активной Collaboration с несколькими видимыми пулами одной ориентации. Раскладка внутри каждого пула совпадает с изолированной с точностью до общего переноса. Смешанные ориентации остаются следующим расширением.

На одиночной плоскости сохранены `finishFixedAnnotations` и текущий проход подписей шлюзов. Например, на `invoice-approval` существующая β размещает заметку Policy в (190, 103). При добавлении несвязанного пустого пула расширенный проход ставит ту же заметку в (188, 74) и прокладывает прямую PolicyLink. В процессе без пула `annotation.bpmn` прежняя позиция Note после раскладки (90, 47), а предпочтение по дельте её опоры (110, 20). Сохранение одиночного пути удерживает действующие позиции, маршруты и результаты повторной раскладки.

В `graph-layout-current.json` обновлены ожидания для `collaboration` и `order-fulfilment`. Хэши уже поддерживаемых кейсов совпали. Проверка сравнивает отпечатки прежнего движка отдельно с исходным baseline. Прежние 294 прогона с возмущённым DI сохранены. Добавлены 12 прогонов с перестановкой DI и заменой прежних точек MessageFlow.

| Схема | Площадь всего ряда в прежнем движке / β, px² | MessageFlow в прежнем движке / β |
| --- | ---: | --- |
| `collaboration` | 365 800 / 155 400 | 0 / 1 поворот, 270 / 250 px |
| `order-fulfilment` | 897 000 / 341 600 | 0 / 2 поворота, 565 / 580 px |

На обеих схемах у MessageFlow ноль пересечений и общих участков. Дополнительные повороты приняты за сокращение площади ряда с сохранением локальных маршрутов SequenceFlow. На браузерном сценарии с дорожкой, несколькими шлюзами и заметкой проекция именованного SequenceFlow совпала с результатом штатного `LabelBehavior`. Явные рамки применяются для запланированных подписей фигур, MessageFlow и Association.

## Производительность

Apple M1 Pro, Node.js 24.22.3, Chromium 159.0.8154.6. Каждый профиль выполняется один раз холодным и пять раз тёплым. Прежняя нагрузка содержит 200 узлов и 216 SequenceFlow. Коллаборация содержит четыре пула по 50 узлов, 216 SequenceFlow, 24 MessageFlow, восемь заметок и четыре раскрытых подпроцесса. Профиль позднего отказа доходит до последней заметки после готовой раскладки пулов. Атомарность отказа на проходе Association проверяется отдельно тестом маршрутизации.

| Профиль | Node холодный / тёплая медиана, мс | Chromium холодный / тёплая медиана, мс | Самые длинные тёплые задачи Chromium, мс |
| --- | ---: | ---: | --- |
| Исходный процесс до изменений | 248 / 72 | 335 / 145 | 52, 0, 0, 0, 65 |
| Процесс после изменений | 256 / 65 | 344 / 139 | 56, 0, 0, 0, 0 |
| Четыре пула | 441 / 206 | 564 / 329 | 121, 111, 119, 111, 111 |
| Поздний отказ | 285 / 104 | 403 / 155 | 0, 0, 0, 0, 0 |

Chromium измеряет от клика до предпросмотра или сообщения об отказе. Ноль в последнем столбце означает отсутствие зарегистрированной Long Task в измеренном интервале.

| Локальная раскладка | 79,9 | 154,1 |
| Размещение пулов | 0,1 | 0,2 |

Цель в одну секунду достигнута. На итоговом сценарии порог длинной задачи в 200 мс достигнут в 0 из 5 тёплых запусков. Перенос в Web Worker отложен.
