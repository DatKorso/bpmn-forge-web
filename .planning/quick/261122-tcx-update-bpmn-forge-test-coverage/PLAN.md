# Навести порядок в тестах BPMN Forge

Переписать устаревшие сценарии, убрать проверки, которые проходят за счёт самих тестовых данных, и добавить один браузерный регрессионный тест в GitHub Actions. Исходная точка — 77 из 77 тестов проходят на Node.js 24.22.3.

## 1. Обновить тесты выравнивания

- **Заменить сценарий с недопустимым выделением подпроцесса.** Получать выделение через `alignmentSelection`. Проверить, что редактор отклоняет совместный выбор задачи и раскрытого подпроцесса. Затем выбрать дорожку с ними и проверить, что подпроцесс, его внутренние узлы и точки маршрута смещаются на один вектор, а размеры подпроцесса сохраняются. Такой сценарий уже подтверждён отдельным прогоном.
- **Проверять итоговое положение узлов в дорожках.** Заменить чтение исходных `.lane` на проверку, что итоговые рамки узлов находятся внутри соответствующих дорожек после выравнивания. Покрыть вертикальный пул и вложенные дорожки в обеих ориентациях.
- **Перенести проверки рамок на уровень планировщика.** Использовать существующие сценарии роста тесного пула, подгонки выбранного контейнера и отказа при нехватке места. Проверить 40 единиц отступа от полезной области, включая граничное событие, и отсутствие изменений при отказе. В тестах `layoutRegion` сохранить проверки графа, сетки, расстояний и повторного запуска. В сценарии на 15 переходов сохранить весь граф и убрать искусственные границы пула.
- **Убрать лишнюю проверку петли и ослабить привязку к координатам ветки.** Удалить сравнение `source === target` для `b-b`, сохранив отдельный тест входа и выхода петли. В сценарии с препятствием проверять, что узел остаётся вне занятого промежутка, маршруты обходят препятствие и прямой входящий поток сохраняется. Назвать эти тесты по поведению ветки из одного узла, которое проверяет алгоритм.

## 2. Ускорить тест метаданных сборки

Экспортировать существующий `formatVersion` из внутреннего скрипта сборки и проверить значения `0.09.4`, `0.10.0` и `0.100.0` напрямую. Проверку истории оставить на реальном временном репозитории с 21 коммитом, доступным из собираемой ревизии, и одним более новым коммитом за её пределами. Проверить лимит в 20 записей, первую запись, ссылку на историю и результат на detached HEAD. Сохранить сценарии merge, squash, неполной истории и отсутствующего базового коммита.

## 3. Добавить браузерный автотест в CI

Для CI использовать **Playwright с Chromium**. Доступный webcmd запускает локальную браузерную сессию в оконном режиме. Воспроизводимый запуск полного сценария с загрузкой и скачиванием файлов на `ubuntu-latest` не подтверждён. Playwright документирует установку Chromium и запуск на GitHub Actions. [Webcmd](https://github.com/agentrhq/webcmd) · [Playwright CI](https://playwright.dev/docs/ci)

- Добавить `@playwright/test` в зависимости для разработки и команду `npm run test:e2e`. Хранить сценарий в `e2e/` с расширением `.spec.js`, чтобы `npm test` продолжал запускать текущий набор через `node --test`. Поднимать Vite Preview через `webServer` Playwright и проверять собранный `dist`. [Playwright Web server](https://playwright.dev/docs/test-webserver)
- Добавить небольшую BPMN-фикстуру с тесным пулом, двумя дорожками, именованным шлюзом, граничным событием и потоками. Через интерфейс редактора открыть и скачать исходную схему, выровнять её, затем выполнить отмену, повтор и ещё одно выравнивание. Скачать BPMN, открыть скачанный файл и выгрузить его снова.
- Сравнивать содержимое XML по BPMN ID. Проверить, что выравнивание изменило геометрию пула, узлов и маршрутов, отмена восстановила исходную геометрию, а повтор восстановил выровненную. Повторное выравнивание и открытие выгрузки должны сохранять рамки фигур и подписей, точки маршрутов, `flowNodeRef`, `sourceRef` и `targetRef`. Сравнивать разобранные данные XML, чтобы форматирование файла не влияло на тест.
- В существующем задании GitHub Actions после `npm run build` выполнить `npx playwright install --with-deps chromium` и `npm run test:e2e` до публикации сборки. Сохранять трассу Playwright при падении. Добавить команды локального запуска в README. [Playwright Browsers](https://playwright.dev/docs/browsers)

## Приёмка

На Node.js 24 проходят `npm ci`, `npm test`, `npm run build` и `npm run test:e2e`. Браузерный сценарий проходит в GitHub Actions на pull request. Поведение редактора и формат BPMN сохраняются. При приёмке отдельно зафиксировать время теста метаданных до и после правки.
